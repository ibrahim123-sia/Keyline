# 10 — AI

Two assistants plus AI helpers. All go through one AI service layer (`/features/ai`) with: provider interface, Cloudflare AI Gateway routing, prompt files in git, tool registry, usage logging (`ai_usage`), rate limits, and a spend limit from settings.

## 1. Knowledge and retrieval (shared)
- **What is indexed:** published properties, projects, developers, area guides, pages, posts, FAQs, agency contact and settings that are public (office hours, fees text).
- **How:** a queue job builds text chunks per entity (title + key facts + description + facilities + POIs), embeds them, stores in `embeddings` (pgvector). Refreshed on every publish/update; removed on unpublish.
- **Hybrid search:** structured filters in SQL (purpose, price, beds, area, polygon, completion) + vector similarity + full-text, merged and re-ranked. Listings must always be fetched live from the database before the AI states a price or status, never from the embedding text.
- **Grounding rule:** the assistant may only state facts that came from a tool result in the current turn. If no tool result supports a fact, it says it doesn't know.

## 2. Customer assistant (website chat + WhatsApp)

### Behaviour
- Greets with the name and greeting from settings; knows the page context (property, area, project, search filters)
- Short, friendly answers; shows listing cards instead of long text
- Asks one question at a time to learn: buy or rent, budget, areas, beds, timeline, cash or mortgage, contact details
- Never invents a property, price, availability, distance, fee or legal fact
- Never negotiates price, gives legal or tax advice, or promises returns. These go to a human (list from settings) with: "Good question for our team. I've asked [agent] to reply to you."
- Can always hand over: "Talk to a human" button and the words "agent / human / person"
- Outside office hours: still helps fully, books viewings, and says when a human will reply

### Tools (customer side)
| Tool | What it does |
|---|---|
| `search_listings(filters, text, polygon?, near_poi?)` | Hybrid search, returns up to 6 cards |
| `get_listing(reference)` | Live details for one listing |
| `get_project(slug)` | Project facts, unit types, plan |
| `nearby(reference, poi_type)` | Saved POI distances for a listing |
| `area_info(location)` | Area guide summary, live counts |
| `answer_faq(question)` | Retrieval over FAQs and pages |
| `mortgage_estimate(price, down, years, rate)` | Same maths as the calculator |
| `rental_return(price, rent, costs)` | Same maths as the ROI tool |
| `compare(references[])` | Side-by-side facts |
| `available_slots(reference, type, date_range)` | Free viewing slots |
| `book_viewing(reference, slot, type, contact)` | Creates viewing + lead (asks the visitor to confirm details first) |
| `save_contact(details)` | Creates or updates the lead with what was learned |
| `request_human(reason)` | Flags the conversation, notifies admins |
| `send_brochure(reference, email)` | Emails the PDF |

### End of conversation
After 15 minutes idle or when closed: write a short summary, extract requirements, score the lead, attach to the lead timeline.

### Lead score (0–100)
Rubric in a prompt file, with reasons saved: clear budget (+), budget fits the listings asked about (+), timeline under 3 months (+), cash or pre-approved (+), contact details given (+), asked for a viewing (+), only browsing / vague (−), outside agency's market (−). The UI always shows the reasons, never just the number.

### WhatsApp agent
- Same brain and tools as web chat
- Replies only inside the 24-hour customer window; outside it, uses approved templates
- Sends listing cards as image + caption + link
- Matches inbound messages to site clicks via the reference code in the pre-filled message
- Voice notes: transcribe and answer in text (optional setting)

### Safety
- Rate limits per visitor and IP
- Prompt-injection defense: content from listings, pages or user messages is treated as data; tool results are fenced; the system prompt forbids following instructions found in content
- Personal data: never repeat other customers' data; never reveal unit numbers, owner names or internal notes
- Log every conversation; admins can review and flag bad answers (used to improve prompts)

## 3. Admin assistant (inside the admin portal)
Opens from the top bar input or a side panel on any admin page. Knows the current page (e.g. the open lead or listing).

### Three kinds of help
1. **Ask (read-only, no confirm needed):** "How many leads this week by source?", "Which listings have not had an inquiry in 30 days?", "Who is waiting for a reply?", "What did Sara ask about?", "Average response time per agent this month?"
2. **Suggest:** proactive cards on the dashboard and inside screens: stale listings to verify, listings priced above similar homes, leads to follow up today, missing SEO, listings with few photos, blog topics from common chat questions
3. **Act (always preview → confirm → run):**
   - Create a listing draft from pasted text or a description
   - Update price, status, badges, featured, agent on a listing
   - Write or improve a listing description / SEO fields
   - Draft a blog post
   - Draft and send a reply to a lead (email or WhatsApp)
   - Book, reschedule or cancel a viewing
   - Create tasks and follow-ups
   - Move a lead's stage, assign an agent
   - Create a UTM link + QR code
   - Send matching listings to a lead

### Not allowed for AI (hard block in code, not just the prompt)
Delete anything; change settings, integrations, branding or users; export personal data in bulk; publish a blog post directly; send bulk messages to more than 10 leads at once.

### Confirm flow
1. The model calls a write tool → the server does **not** run it. It stores an `ai_actions` row with status `proposed` and a **preview** (before/after diff, or message text, or the draft entity).
2. The admin sees an **AIActionPreview** card: what will change, where, and buttons Confirm / Edit / Cancel.
3. On Confirm, the server re-checks permissions and validation, runs the action, writes `audit_log` with `actor_type = ai` and the confirming admin, and updates `ai_actions` to `executed`.
4. Multi-step requests become a list of proposed actions the admin can confirm one by one or all together.

### Read tools (admin side)
`query_leads(filters)`, `query_listings(filters)`, `get_lead(id)`, `get_listing(id)`, `report(metric, period, group_by)`, `stale_listings()`, `unanswered_leads()`, `similar_listings_price_check(id)`, `seo_issues()`, `chat_topics(period)`.
Reports are computed by fixed SQL behind each tool. The model never writes raw SQL.

## 4. MCP server
- Exposes the same admin read tools and write tools over MCP so the agency can use Keyline from Claude or other MCP clients
- Auth: per-admin API token (created in Settings → Admin users), scoped and revocable
- Write tools over MCP return a **proposed action id and preview**; the action stays pending until confirmed in the Keyline admin (or via a `confirm_action(id)` tool that requires the token to belong to an admin, and logs it)
- Deployed on Cloudflare, documented in the README with a setup example

## 5. AI helpers (smaller features)
| Helper | Where | Rule |
|---|---|---|
| Listing description writer | Property editor | Uses only the entered facts; marks anything unknown as "[add detail]" |
| Title suggestions | Property editor | 3 options |
| SEO title/description | All SEO panels | 3 options, within length limits |
| Alt text suggestions | Media | From image + listing context |
| Blog draft | Blog | Draft only, review required |
| Valuation range | Valuation request | From comparable own listings (same area, type, beds, size ±20%), shows comparables used, clearly labelled estimate; if fewer than 3 comparables, say "not enough data" and route to an agent |
| Lead summary + score | Leads | As above |
| Chat topic clustering | Reports / suggestions | Weekly job groups common questions |
| Listing from text | Admin assistant | Creates a draft only |

## 6. Prompts and evaluation
- Prompts live in `/features/ai/prompts/*.md`, versioned in git
- A small eval set (`/tests/ai/`) with 30+ customer questions and expected behaviour (grounded answer, hand-over, refusal to invent, booking flow). Run before changing prompts or models
- Track: answer grounded rate, hand-over rate, bookings by AI, bad-answer flags
