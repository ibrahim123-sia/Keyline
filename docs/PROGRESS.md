## Phase 1 — Foundation (plan)

1. Repo scaffold: Next.js 16.4 (App Router, RSC, Server Actions), TypeScript strict, Tailwind v4, shadcn/ui, ESLint (flat) + Prettier, Vitest, Playwright.
2. Database: Drizzle ORM + Drizzle Kit, migrations in git, PostGIS / pgvector custom types; local PostgreSQL 18 via PGlite server (`pnpm db:start`); core schema: users (+ Better Auth tables), settings, secrets, audit_log, agents, media.
3. Settings: typed JSON per group (Zod schemas with defaults), cached loader (`'use cache'` + `cacheTag('settings:<group>')`), revalidated on save.
4. Auth: Better Auth (email + password, email verification, password reset, optional Google for customers), roles `admin` | `customer`, TOTP 2FA for admins, session lengths (customer 30 days, admin 12 hours).
5. Permission helpers (`requireAdmin`, `requireCustomer`, `assertCan`) used by every admin page, action, route handler and AI tool. Audit log helper.
6. Design tokens: CSS variables generated from Branding settings, injected in the root layout; Desert Modern defaults.
7. Base layouts: site header/footer shells, account shell, admin sidebar + top bar (light/dark per admin).
8. i18n: one dictionary per area (`site`, `account`, `admin`), logical CSS properties only.
9. Cloudflare: OpenNext adapter, `wrangler.jsonc` with `staging` and `production` envs, custom worker (fetch + queue + scheduled), Hyperdrive, R2, Queues bindings.
10. CI: GitHub Actions — lint, type check, unit tests, migration check, Playwright; deploy to staging when Cloudflare secrets exist.
11. Setup command `pnpm admin:create` for the first admin.

Done-when checklist (from `15-build-phases.md`):

- [ ] `staging` deploys from CI and loads — _needs Cloudflare + Neon credentials (see Open questions)_
- [x] First admin can be created with a setup command and can sign in with 2FA (e2e)

## Decisions (made by me, per spec 01 §5 "small decisions")

1. **Working mode.** The owner asked (chat, 2026-10-20) for the whole project to be built end to end with feature-by-feature commits and pushes, reviewing and testing everything myself. So I write each phase plan here and proceed without waiting for approval between phases.
2. **Local database = PGlite.** This machine has no Docker or PostgreSQL. `@electric-sql/pglite` 0.5.10 is PostgreSQL 18.6 compiled to WASM and supports `postgis`, `vector`, `pg_trgm` and `unaccent`. `pnpm db:start` exposes it over the normal Postgres wire protocol (`@electric-sql/pglite-socket`), so the app uses the same `pg` driver locally and on Workers. Verified: ST_DWithin (geography), ST_Within/ST_Contains with GeoJSON polygons, HNSW cosine search, trigram similarity, `unaccent`, full-text search, concurrent connections and transactions. Production stays on Neon via Hyperdrive. PGlite is a dev/test dependency only.
3. **DB driver = `pg` (node-postgres).** That is what the OpenNext Cloudflare docs use with Hyperdrive. On Workers a small pool is created per request (`maxUses: 1`) because I/O objects cannot be shared across requests; in Node a single pool is reused.
4. **Caching model = Next.js 16 Cache Components.** `cacheComponents` + `partialPrefetching` are the Next 16.4 defaults and OpenNext lists composable caching (`'use cache'`) and PPR as supported. Public data functions use `'use cache'` + `cacheLife` + `cacheTag`; mutations call `updateTag`/`revalidateTag`. This gives the per-entity revalidation the spec asks for (listing → its search results → its project page).
5. **`middleware.ts`, not `proxy.ts`.** Next 16 renamed middleware to proxy, but proxy only runs on Node.js and OpenNext does not support Node middleware yet. Edge `middleware.ts` is still supported and is what spec 01 asks for.
6. **Library versions.** Locked-stack tools use their current versions (Next 16.4.2, React 19.3, Tailwind 4.3, Drizzle 0.45, Better Auth 1.7, OpenNext 1.20, Tiptap 3). Where a new major shipped very recently, I use the previous major, which is still maintained: TypeScript 5.9 (Next's template pins `^5`; TS 7 is the new native compiler), ESLint 9, Vitest 4, TanStack Table 8, `@hookform/resolvers` 5. MapLibre GL is on 6.13 (not 5.x) because every version up to 6.4.0 has a critical XSS advisory (GHSA-jrc7-96c5-q579).
7. **`tsx`** runs TypeScript scripts (migrate, seed, setup commands). Dev dependency only.
8. **Single tenant `agency_id`.** Every main table has `agency_id` (uuid). Its value comes from `AGENCY_ID` in the environment. There is no `agencies` table (out of scope); adding one later is a small migration.
9. **IDs.** UUID v7 generated in app code (`lib/ids.ts`), so ids are known before insert (needed for audit `entity_id` and for linking rows in one transaction).
10. **Line endings.** `.gitattributes` forces LF; `core.autocrlf=false` in this clone.
11. **Own PGlite wire bridge (`scripts/pglite.ts`) instead of `@electric-sql/pglite-socket`.** The socket server forwards an extra ReadyForQuery that PGlite's backend emits after an error in an extended-protocol message, so every later result on that connection is shifted by one (reproduced with a unique violation and with a trigger error). The bridge buffers each client batch up to Sync, skips the rest of a failed batch until Sync, forwards ReadyForQuery only for Sync/Query, and gives the session to one connection while it is inside a transaction (from the ReadyForQuery status byte). Verified: error sequences, aborted transactions, pipelining, a pool with mixed errors, crash recovery after a hard kill.
12. **Search helpers in SQL.** `lintel_unaccent()` / `lintel_normalize()` are IMMUTABLE wrappers (unaccent itself is only STABLE) so they can be used in generated columns and trigram indexes.
13. **Vitest uses Vite's native `resolve.tsconfigPaths`** (no extra plugin).
14. **Accent on accent-soft is for icons only.** With the Desert Modern defaults, terracotta text on its soft tint is 4.44:1 (below the 4.5:1 rule). Accent icons on the tint pass the 3:1 UI-graphics rule; badge/label text on the tint uses ink. The branding contrast report checks both pairs.
15. **Form-control borders** use a mix of the muted text colour (≥ 3:1, WCAG 1.4.11) instead of the decorative border token (~1.3:1 on white).
16. **shadcn/ui 4 (Radix base, `rtl: true`)** so generated components use logical properties. shadcn's `accent` (hover background) is replaced by `muted` in components because `--color-accent` is the spec's terracotta token. Toasts do not use next-themes (light site, admin passes its theme).
17. **Audit log is append-only in the database** (trigger blocks UPDATE/DELETE/TRUNCATE), not only in app code. Test clean-up uses `session_replication_role = replica`.
18. **Maps = MapLibre GL 5 + terra-draw.** Tiles come from Settings -> Integrations (style URL or MapTiler key); without one, the keyless OpenFreeMap "positron" style is used so maps always work. MapLibre loads only when the map scrolls into view.
19. **Google Maps Platform sits behind a `MapsProvider` interface** (Geocoding, Places Nearby (New), Routes matrix). Without a server key every caller gets a clear "add a key" message; tests use a fake provider.
20. **Slug changes create 301 redirects automatically** for every public path of that entity, and the redirects table is kept free of chains (A->B->C becomes A->C) and loops.
21. **Admin tables are URL-driven.** Page, sort, search and filters live in the query string, so any view can be bookmarked or shared; the chosen columns are remembered per browser.
22. **Uploads use signed links to our own endpoint**, which writes to R2 through the Worker binding. Same protection as R2 presigned URLs (signed, 30-minute expiry, exact size, single use) plus the link only works for the admin who asked for it, and no S3 API keys or bucket CORS are needed. Raw uploads sit under a private `incoming/` prefix that `/media` never serves.
23. **Metadata strip is lossless, in plain TypeScript.** Instead of re-encoding (which costs listing-photo quality), the pipeline rewrites the container: drops EXIF (GPS, serials), XMP, IPTC, comments, thumbnails and anything appended after the image; keeps the ICC profile and EXIF orientation. AVIF metadata items are zeroed in place. Files whose structure is broken are refused rather than published. Pixel output is verified byte-identical in tests.
24. **HEIC is converted to JPEG in the browser** with `heic-to` 1.6.5 (libheif 1.23.5, LGPL-3.0, used unmodified, loaded only when a HEIC file is chosen). Cloudflare's Images binding cannot read HEIC (only AVIF among HEIF formats), so the server only tries it as a fallback and otherwise fails the file with "export it as JPEG".
25. **Resized images come from `/media/<key>?w=&q=`.** On Workers the Cloudflare Images binding makes each size once and keeps it in R2 under `variants/`; in development the route hands off to Next's optimizer. OpenNext's `/_next/image` only reads static assets on Workers, so it cannot serve uploads.
26. **SVG is allowed for admins only** (logos), refused when it contains scripts, event handlers, external references, entities or active elements, and served with a sandboxing CSP and `nosniff`.
27. **Placeholder colour** is measured in the browser during upload (a 16x16 downscale averaged); in production the job falls back to a 1x1 Cloudflare Images thumbnail.
28. **Uploadable types:** JPEG, PNG, WebP, GIF, AVIF, HEIC (converted), SVG and PDF, up to the limit in Settings -> General (default 20 MB) and 100 megapixels. Video is linked by URL (05: `video_url`), not uploaded.
29. **`sharp` is a dev dependency** (tests only, same version Next ships) to build real photos with GPS metadata and check that stripped files still decode.
30. **Admin toasts sit bottom-left.** Save buttons are right-aligned and side panels open on the right, so toasts there covered form fields or actions.
31. **The e2e dev server starts cold** (`turbopackFileSystemCacheForDev` off for `.next-e2e`): a restored dev cache next to files edited since (e.g. by the formatter) sent the browser into an endless reload loop. CI runs e2e against a production build anyway.
32. **Field errors follow the input path.** Admin actions take `{ id, data }`; validation errors are keyed by path without the `data` wrapper ("website", "organisation.logoId"), so every form can highlight the field (before, nested errors only reached the toast).
33. **Links must be http(s).** `z.url()` also accepts `javascript:` and `data:` URLs, which run script when clicked; websites and canonical URLs use a shared `httpUrl()` schema instead.
34. **Shared validators live in `lib/schemas.ts`**: http(s) links, international phone numbers (normalised to +E.164) and working hours (up to four ranges a day, no overlaps, end after start), used by agents, contact settings and viewing hours alike.
35. **Saving Security or Integrations settings needs a recent sign-in** (`reauthMinutes`, default 15); the form explains it and offers to sign in again, keeping the edits on screen.
36. **Default pipeline** for a fresh install: New, Contacted, Viewing, Offer (open), Won, Lost, all editable. A pipeline that has an open, a won and a lost stage keeps them: edits or deletes that would remove the last one are refused.
37. **Integration tests make cheap read-only calls** (Resend: list domains, a sending-only key counts as valid; WhatsApp: read the phone number on Graph API v23.0; Anthropic: list models and check the configured ones exist), time out after 10 seconds and keep the outcome on the key.
38. **Webhook tokens Keyline generates are shown once** (to paste into Meta, TikTok, Google Ads or a portal) and masked afterwards, like every other key.
39. **Admin invites reuse Better Auth's password reset** (same screen, rules and token check) with a 7-day token instead of the 1-hour reset token; resending an invite cancels the earlier link. Invites refuse emails that already belong to an admin or a customer, so roles never mix.
40. **API tokens** look like `lnt_` + 40 random characters, are shown once and stored as a SHA-256 hash with an 8-character prefix for recognition; "propose" access lets MCP write tools prepare changes that an admin confirms in Keyline (10 §4).
41. **Listing references** come from a PostgreSQL sequence (`property_reference_seq`, from 1001) with the prefix from Settings -> General, so two admins saving at once never get the same number.
42. **Listing search vector is a generated column** over title, building, reference and `search_text` (location names, kept current on save); generated columns cannot read other tables, so the names are copied in.
43. **Rich text is Tiptap 3.31.4 JSON, rendered to HTML on the server.** The editor allows headings (2 and 3), bold, italic, lists, links (https, mailto, tel) and line breaks; `richDocSchema` accepts only those nodes, marks and attributes, and `renderRichText` escapes all text and sets `rel`/`target` itself. A unit test builds the editor's schema and checks it produces nothing the server would refuse. Stored as `description` (JSON) plus `description_html` (rendered on save).
44. **A payment plan has one owner.** A listing or project saves its own plan with it; a listing in a project without a plan of its own shows the project's plan (07 §5 "inherited by its units, or overridden per listing"). Templates are separate rows (`is_template`) that are copied into a plan, never shared, so editing one listing's plan never changes another. The four built-in templates live in code; an empty short label follows the steps ("60/40", "70/30 post-handover").
45. **The 100% rule** (05 §6): drafts may hold an unfinished plan; templates, and plans shown on live listings or projects, must add up to exactly 100%. Percentages are compared in basis points; amounts per step use BigInt and the largest remainder, so they always add up to the price.
46. **Saved views are shared by the agency's admins** (`saved_views`, per table): the URL filters without paging or search, next to built-in views ("Drafts", "Needs verification", "Off-plan", "No photos", "Archived"). Leads reuse them in Phase 6.
47. **Listing status:** draft is private; publishing (to available, reserved or under offer) checks the publish rules; sold and rented keep their page but leave search; off market hides the page. The first publish sets `published_at` and stores the price as `original_price`; automatic badges ("New", "Price reduced", "Verified", "Off-plan") are recomputed on every change and daily, and never touch a badge added by hand. Archive is a soft delete with restore.
48. **Parallel work in git worktrees** (D:/Keyline-wt/*, each with its own pnpm install; never a junction to the main node_modules, which git follows when removing a worktree). Memory-heavy commands go through one shared lock, one at a time; agents call binaries directly because pnpm v12 reinstalls before `pnpm run`. Their commits are reviewed and cherry-picked onto main.
49. **Demo pictures are drawn, not stock photos** (16 §1 allows placeholders): sharp renders simple room, building, villa and pool scenes, floor plans marked "Illustrative plan, not to scale", initials portraits and wordmark logos. No licensed images are bundled, and nothing pretends to be a real photo.
50. **Missing slugs are "soft 404s".** Public pages stream (Cache Components), and Next.js 16 sends a streamed page with status 200 (docs: loading -> Status codes). A missing listing, project, developer, agent or area renders the helpful 404 page with `noindex`; routes that do not exist at all return a real 404. A real 404 for slugs would need a database check in the proxy, which runs on the edge without database access here.
51. **Core Web Vitals are measured in CI**: Lighthouse 13.5.0 (dev dependency) runs its default mobile profile (a mid-range phone on simulated 4G) against a seeded property page on the production build and fails the job above LCP 2.5 s, CLS 0.1 or TBT 200 ms (the lab stand-in for INP).
52. **Visitor id and consent:** the first-party `vid` cookie is set by the middleware on the first site request (a year, per 09 §2); when the visitor refuses analytics cookies it becomes a session cookie with the same id, so the visit can still be attributed. It is only sent when new or when consent changes, so cached pages do not carry a cookie on every response. Journey events (page views, searches, listing views) are stored only with analytics consent; contact clicks (WhatsApp, call, form sent) always, because the lead needs them; listing view, share and brochure counters are stored without any visitor id.
53. **Channel rules** follow 09 §2 in order, with three additions: a campaign link with an unknown medium and no referrer counts as a referral (it still carries its campaign), webmail referrers (Gmail, Outlook) count as email, and portal names match `utm_source` ignoring spaces and dashes. `fbclid` counts as paid social as the spec says, although Facebook also adds it to organic links.
54. **Lead capture is synchronous, the rest is a job:** dedupe, assignment and the timeline happen in one transaction when the form is sent (so two quick messages from one person join one lead); notifications, the auto-reply and scoring run after commit in `lead.process` and `lead.score`, and a retried job never sends an email twice.
55. **Assignment falls through** the rule in Settings -> Leads: listing agent -> area match (an agent covering the area or any area above it) -> round robin (the active agent given a lead longest ago, `agents.last_assigned_at`); "manual" leaves leads unassigned, and an open lead without an agent is assigned when it next gets a message.
56. **Requirements from the asked-about listing** (purpose, area, type, beds) fill only what the lead did not say; the budget becomes a band of 15% either side of the price, marked as worked out (`budgetFrom: listing`). A budget the lead states replaces it, and only a stated budget scores.
57. **Lead score by rules until Phase 9:** the 10 §2 rubric with points and reasons (budget +15, fits +10, timeline under 3 months +15, cash or pre-approved +10, email and phone +10 or one of them +5, viewing +15, vague -15, from a base of 30); the reasons are stored with the number. The AI scores with the same rubric once it is on.
58. **Message templates** have built-in wording in code with `{{variables}}`; an agency's own version (`message_templates`) wins, and a template can be turned off. Emails use the branded layout.
59. **"Admins" in the notification matrix** means the agency's lead inbox (Settings -> Contact lead alert emails, else the main email), as with the Phase 4 forms; a new lead goes to the agent and that inbox as Settings -> Notifications says.
60. **Tour requests from the listing page** become leads with an "Arrange a tour" task until the booking flow with real free slots replaces the dialog (Phase 6 viewings).
61. **Campaign links (09 §2)** point only at pages on this site (a full address on another host is refused, so `/go/<code>` can never be an open redirect). Short codes are five characters without look-alikes; clicks from bots and link previews (WhatsApp, crawlers) are not counted; an unknown or deleted code lands on the home page, because printed QR codes outlive campaigns. QR codes are drawn on demand (SVG, PNG from it in the browser) with `uqr`, already used for two-step setup, instead of being stored (`qr_svg_key` is not needed).
62. **The Lighthouse check reports instead of failing until the Phase 10 performance pass.** On the property page the lab run estimates LCP at about 3.4-3.6 s (target 2.5 s; CLS 0 and TBT about 50 ms pass). The image itself is small and preloaded; the estimate is high because on localhost every script finishes before the first paint, so Lighthouse's simulation counts all of them (about 320 KB) against LCP; with applied throttling the first paint waits for the framework script. Done so far: no Zod in the browser, toasts and recently viewed load later, icons drawn on the server, the landing beacon after load, no clock reads while prerendering. Open for Phase 10: the page data is sent twice in the HTML (about 67 KB each; the second copy is the App Router's segment data, to look at with `partialPrefetching`), Radix menus and dialogs loaded only when opened, and a PageSpeed Insights run against staging. `LIGHTHOUSE_ENFORCE=1` makes the test fail on the targets again.
63. **Page builder:** drafts save even with unfinished sections (flagged in the editor), and Publish refuses until every section is complete; page settings (title, slug, template, SEO) apply at once rather than through the draft; scheduling a live page publishes its pending changes later and keeps it up meanwhile; restoring a revision puts it into the draft, not on the site. A slug change on a page that was ever published adds an automatic redirect, served as 308 like listing pages (the table stores 301). Custom HTML sections are always cleaned unless Settings -> Security allows scripts.
64. **Area guides and links:** a menu link of type "area" opens the area's published guide, else its homes for sale; average prices per area unit on a guide show only with 3 or more homes; guide numbers always carry a source note.
65. **Channels:** a WhatsApp message outside the 24-hour window can only be an approved template, and the composer switches to template mode; when WhatsApp is not set up, a send is stored as failed with the reason, never shown as sent. Web chat is off by default (Settings -> AI) until the assistant arrives in Phase 9.
66. **Shortlists** ("send properties", 09 §4) are personal links at /s/[token] (noindex) that count opens and which homes were opened.
67. **Site bookings are confirmed at once** (the visitor picked a real free time); the agent can still move or cancel them. Phone is required for a viewing, email optional (it carries the confirmation).
68. **Redirects are served by the middleware** with a real 301/302: a streamed page (Cache Components) cannot change its 200 status, so the middleware keeps the redirects table per instance for 5 seconds, refreshed from `/api/internal/redirects` (through the service binding on Workers), and reports hits. A new rule reaches it within seconds; until then pages still redirect themselves. Unknown addresses are real 404s (no catch-all route); missing slugs on existing routes stay soft 404s with `noindex` (decision 50).
69. **Newsletter confirm and unsubscribe links do nothing until their button is pressed**, so mail scanners that open links cannot confirm or unsubscribe anyone; the unsubscribe link is signed from the subscriber id, so no token is stored.
70. **Alerts never repeat**: each alert is recorded with its email in one transaction (search or saved home, listing, kind, and the new price or status), so a raced job rolls back and a second drop to a new price sends again. Digests cover listings first published since the search's last email; a listing back from off market alerts instantly but is not in digests (a "went live at" column would fix that).
71. **Google Calendar busy times are polled every 15 minutes** (push notifications are left for later); a viewing's Google event follows it through a retried job, and nothing is called while the integration is not set up.
72. **Past activity is linked by verified email only**: phones are not verified, so linking by phone could hand someone else's inquiries to a stranger. Linking happens when a session is created.
73. **Deleting an account anonymises what the agency must keep** (leads, viewings, messages) and deletes the rest; the audit entry uses actor type "system" with `requestedBy: "customer"`, as there is no customer actor type.
74. **Rich text sent to Server Actions is plain JSON**: the editor's node attributes are not plain objects, so a Server Action received them as opaque references and validation failed; the editor serialises its document before `onChange`.
75. **Shortlist opens are counted by the browser**, with a beacon sent once the page has loaded, not while it renders: a render can repeat (production rendered the page twice for one visit), and link scanners and chat previews fetch the page without running it.
76. **Repository layout**: the code keeps the spec's folder structure at the root (`01-rules-and-stack.md` §3: `app`, `components`, `features`, `db`, `lib`, `jobs`, `emails`, `tests`), as usual for a Next.js app, rather than moving into `src/`. Documentation lives in `docs/` (the spec in `docs/spec/`, this file in `docs/`), contributor and security guides in `.github/`.
